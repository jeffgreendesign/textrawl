Textrawl supports two embedding providers for generating vector representations of your documents.

## Provider Comparison

| Feature | OpenAI | Ollama |
|---------|--------|--------|
| Location | Cloud API | Local/Self-hosted |
| Model | text-embedding-3-small | nomic-embed-text |
| Dimensions | 1536 | 1024 |
| Cost | $0.02 / 1M tokens | Free (compute costs) |
| Latency | 100-300ms | 50-200ms (local) |
| Privacy | Data sent to OpenAI | Fully local |
| Offline | No | Yes |

<Aside type="danger">
  OpenAI and Ollama use different embedding dimensions. You **cannot** mix providers without re-embedding all documents.
</Aside>

## OpenAI (Default)

### Configuration

```bash
EMBEDDING_PROVIDER=openai
OPENAI_API_KEY=sk-proj-...
```

### Model: text-embedding-3-small

- **Dimensions**: 1536
- **Max tokens**: 8,191
- **Quality**: Production-ready, good for most use cases
- **Cost**: $0.02 per 1 million tokens

### Database Schema

Use `scripts/setup-db.sql`:

```sql
-- Chunks table with 1536-dimension vectors
CREATE TABLE chunks (
  ...
  embedding vector(1536)
);

-- HNSW index for fast similarity search
CREATE INDEX ON chunks
USING hnsw (embedding vector_cosine_ops);
```

### Cost Estimation

| Knowledge Base | Avg Doc Size | Embeddings | Monthly Cost* |
|----------------|--------------|------------|---------------|
| 1,000 docs | 2,000 tokens | 2M tokens | ~$0.04 |
| 10,000 docs | 2,000 tokens | 20M tokens | ~$0.40 |
| 100,000 docs | 2,000 tokens | 200M tokens | ~$4.00 |

*One-time embedding cost; searches use cached embeddings.

## Ollama (Local)

### Configuration

```bash
EMBEDDING_PROVIDER=ollama
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_MODEL=nomic-embed-text
```

### Setup

<Tabs>

</TabItem>

### Model: nomic-embed-text

- **Dimensions**: 1024
- **Max tokens**: 8,192
- **Quality**: Competitive with OpenAI for most tasks
- **Cost**: Free (your compute only)

### Database Schema

Use `scripts/setup-db-ollama.sql`:

```sql
-- Chunks table with 1024-dimension vectors
CREATE TABLE chunks (
  ...
  embedding vector(1024)
);

-- HNSW index

```

## How Embeddings Work

### Text → Vector

```text
"quarterly budget meeting"
         │
         ▼
   Embedding Model
         │
         ▼
[0.023, -0.045, 0.089, ..., 0.012]  (1536 or 1024 floats)
```

### Similarity Search

```text
Query embedding: [0.023, -0.045, ...]
                      │
                      ▼
            Cosine Similarity
                      │
    ┌─────────────────┼─────────────────┐
    ▼                 ▼                 ▼
Chunk A: 0.92    Chunk B: 0.87    Chunk C: 0.45
(most similar)   (similar)        (less similar)
```

### Cosine Similarity

Measures angle between vectors:

- 1.0 = Identical direction (very similar)
- 0.0 = Perpendicular (unrelated)
- -1.0 = Opposite direction (very different)

## Performance Optimization

### Batch Embedding

Textrawl batches embedding requests:

```typescript
// Instead of:
for (chunk of chunks) {
  await generateEmbedding(chunk);  // N API calls
}

// Textrawl uses:
await generateEmbeddings(chunks);  // 1 API call
```

Batch size: 50 (configurable via `--batch-size`)

### HNSW Index

Hierarchical Navigable Small World graph:

- **Build time**: O(n log n)
- **Query time**: O(log n)
- **Memory**: ~1.5x vector size

Parameters in schema:

```sql
CREATE INDEX ON chunks
USING hnsw (embedding vector_cosine_ops)
WITH (m = 16, ef_construction = 64);
```

| Parameter | Default | Description |
|-----------|---------|-------------|
| m | 16 | Connections per layer |
| ef_construction | 64 | Build-time search width |

Higher values = better recall, slower builds.

## Migration Between Providers

Switching providers requires re-embedding:

<Steps>

1. **Backup existing data**

   ```sql
   -- Export documents (content preserved)
   COPY documents TO '/tmp/documents.csv' CSV;
   ```

2. **Update schema**

   ```sql
   -- Drop old chunks table
   DROP TABLE chunks;

   -- Run new schema (Ollama example)
   -- Paste scripts/setup-db-ollama.sql
   ```

3. **Update environment**

   ```bash
   EMBEDDING_PROVIDER=ollama
   OLLAMA_BASE_URL=http://localhost:11434
   ```

4. **Re-upload documents**

   ```bash
   # Force re-upload to regenerate embeddings
   npm run upload -- ./converted/ --force
   ```

</Steps>

## Troubleshooting

### "OpenAI not configured"

```bash
# Check environment
echo $OPENAI_API_KEY

# Verify in .env
cat .env | grep OPENAI
```

### "Ollama connection refused"

```bash
# Check if Ollama is running
curl http://localhost:11434/api/tags

# Start Ollama
ollama serve
```

### "Model not found"

```bash
# Pull the model
ollama pull nomic-embed-text

# Verify
ollama list
```

### Dimension mismatch errors

```
ERROR: column "embedding" is of type vector(1536) but expression is of type vector(1024)
```

You're using the wrong schema for your provider. Either:
- Switch to the matching provider, or
- Recreate the database with the correct schema
