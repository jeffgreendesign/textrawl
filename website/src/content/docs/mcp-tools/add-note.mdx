Create markdown notes in the knowledge base with automatic chunking and embedding for search.

## Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `title` | string | Yes | Note title (1-500 characters) |
| `content` | string | Yes | Markdown content (1 char - 1MB) |
| `tags` | string[] | No | Tags for organization |

## Example Request

```json
{
  "title": "Meeting Notes: Product Roadmap Discussion",
  "content": "# Product Roadmap Discussion\n\n## Attendees\n- Alice (PM)\n- Bob (Engineering)\n- Carol (Design)\n\n## Key Decisions\n\n### Q1 Priorities\n1. Launch mobile app v2.0\n2. Implement SSO integration\n3. Redesign dashboard\n\n### Timeline\n- Mobile app: February 15\n- SSO: March 1\n- Dashboard: March 30\n\n## Action Items\n- [ ] Alice to create Jira epics\n- [ ] Bob to estimate engineering effort\n- [ ] Carol to share mockups by Friday",
  "tags": ["meetings", "product", "roadmap", "2025"]
}
```

## Response

```json
{
  "success": true,
  "documentId": "7c9e6679-7425-40de-944b-e07fc1f90ae7",
  "title": "Meeting Notes: Product Roadmap Discussion",
  "chunksCreated": 2,
  "message": "Note saved and indexed for search."
}
```

## How It Works

When you add a note, Textrawl:

1. **Creates document**: Stores the full content in the `documents` table
2. **Generates tsvector**: Creates full-text search tokens for keyword matching
3. **Chunks content**: Splits into ~512 token chunks with 50 token overlap
4. **Generates embeddings**: Creates vector embeddings for each chunk
5. **Stores chunks**: Saves chunks with embeddings in the `chunks` table

### Chunking Details

| Parameter | Value |
|-----------|-------|
| Max chunk size | 512 tokens (~2048 chars) |
| Overlap | 50 tokens |
| Strategy | Paragraph-aware (splits on `\n\n`) |

<Aside type="tip">
  Use markdown headings and paragraphs to help the chunker create logical boundaries.
</Aside>

## Response Fields

| Field | Type | Description |
|-------|------|-------------|
| `success` | boolean | Operation succeeded |
| `documentId` | UUID | New document ID |
| `title` | string | Document title |
| `chunksCreated` | number | Number of chunks generated |
| `message` | string | Confirmation message |

## Error Responses

```json
{

```

### OpenAI not configured

```json
{
  "error": "OpenAI not configured",

```

### Failed to add note

```json
{
  "success": false,
  "error": "Failed to add note",
  "message": "Content exceeds maximum size"
}
```

## Content Guidelines

### Markdown Support

Full markdown is supported and preserved:

- **Headings** (`# ## ###`)
- **Lists** (ordered and unordered)
- **Code blocks** (with syntax highlighting hints)
- **Links** and **emphasis**
- **Tables**

### Size Limits

| Limit | Value |
|-------|-------|
| Title | 500 characters |
| Content | 1 MB (~1 million characters) |

### Structuring for Search

```markdown
# Clear Title

## Section with Keywords

Content with relevant terminology that will be
matched by both semantic and keyword search.

## Another Section

More content...
```

## Best Practices

1. **Use descriptive titles**: Helps with search and browsing
2. **Structure with markdown**: Headings create natural chunk boundaries
3. **Add relevant tags**: Enables filtering in `list_documents` and `search_knowledge`
4. **Keep content focused**: One topic per note improves search precision
5. **Include keywords**: Important terms should appear in the text for full-text matching
